# FREE・PLUS一括バックアップ仕様（v1実装済み）

## 対象

ホワイトリストで以下の利用者データだけをまとめる。localStorageの全項目をそのまま書き出さない。

- free：従来の言葉・お気に入り・衝動記録・演出設定
- money：自己申告の回避額記録
- plan：代替行動と並び順・自分へのメッセージ

契約権限、デモ状態、認証トークン、ログイン情報、Stripe識別子、秘密鍵は一切含めない。購入復元は将来のログインとサーバー側権限確認で別途行う。試算の一時入力や表示中の画面も含めない。

## 実装形式

```json
{
  "format": "hazure-no-kioku-user-backup",
  "version": 1,
  "exportedAt": "ISO 8601の日時",
  "data": {
    "free": "既存のFREEオブジェクト",
    "money": "専用形式の回避額オブジェクト",
    "plan": "専用形式の行動プランオブジェクト"
  }
}
```

上記は構造の説明。実データでは文字列ではなく各オブジェクトを格納する。各データの既存形式・保存キーは維持する。記録のない領域は定義済みの空の形式を格納し、欠けた領域を勝手に全削除と解釈しない。

## 書き出し

各領域を読んで各検証関数を通し、共通形式に格納する。どれかが読み込めない場合、黙って空データに置き換えず一括書き出しを止め、元の専用JSONを退避する方法を案内する。金額・メッセージ・日時を含む個人的なファイルとして取り扱いを明示する。

## 復元手順

1. 容量上限32MB、共通形式、各領域のバージョン・入力値・重複ID・参照を、書き込み前にすべて検証する。
2. 件数・対象領域を画面で提示し、「置き換え」であることを確認する。初期版ではマージをしない。
3. 現在の3領域を一括で書き出すよう案内する。未指定領域を削除しない。
4. 他のタブを閉じてもらい、アプリの更新処理を止める。復元の原本・新データ・進行段階を保存する復元ジャーナルを準備する。ジャーナルを保存できない容量状態なら、元データを変更せず中断する。
5. 3領域を書き込み、読み戻して内容を確認する。失敗時はジャーナルから元の値を戻す。画面更新は完了後に一度行う。
6. 完了後にジャーナルを除去する。再起動時は通常のデータ読み込みより先に未完了ジャーナルを検出し、整合した状態への回復を行う。

localStorageには複数キーを同時確定するトランザクションがない。「完全に原子的な復元」とは説明しない。途中終了・容量不足・復旧自体の失敗をテストし、ジャーナルがある状態で新たな編集を許可しない。旧バージョンを開いた別タブは更新停止に協力しない可能性があるため、他タブを閉じる案内が必要。

より厳密な一括更新が必要になった場合は、IndexedDBのトランザクションへの保存層移行を別の開発として検討する。今回の機能実装には含めない。

## 互換性と権限

従来の3種類の専用JSONは引き続き対応する。専用形式を識別したときは対象領域だけを置き換える。共通形式から購入状態を読み取らず、余分な権限フィールドは拒否または無視し、認証用の保存領域へは一切書き込まない。

利用者自身のバックアップ・削除を購入失効で妨げないよう、将来はデータ管理とPLUS機能編集の権限を分ける。インポートによってPLUS権限が解放されることはない。インポートしたPLUSデータは保全し、編集などのPLUS機能は別のサーバー側購入確認に従う。

## 必要なテスト

3領域の往復、空データ、従来ファイル、重複・過大入力・破損、途中の保存失敗、画面終了後の回復、他タブ、権限フィールド混入、認証情報が書き出されないこと、既存保存形式の維持を確認する。


## 実装と制約

- 設定画面からFREEでも一括書き出し・復元ができる。個別形式の操作は従来の各画面で維持する。
- `backup.mjs`は既存の3検証関数で全領域を検証し、許可したフィールドだけを再構築する。3領域の欠落と未対応バージョンを拒否する。保存キーは固定ホワイトリストで、認証用のキーは読み書きしない。
- 復元ジャーナルは `hazure-no-kioku-restore-v1`。原文のbefore・正規化したafter・prepared/committed状態を保存する。書き込み・読み戻し確認後に確定し、ジャーナルを削除する。
- preparedまたは不一致のジャーナルは元に戻す。committedで新データがすべて一致する場合は完了と判断する。破損や回復失敗では情報を残し、アプリの編集を止める。
- bootstrapは通常モジュールの読み込み前に回復する。復元成功時は全モジュールのメモリ状態を再読み込みし、デモ状態を復元しない。
- Web Locks対応時は復元・起動時の回復を直列化する。別タブのジャーナル更新では編集を止める。ただし旧版のタブやWeb Locks非対応環境との完全な競合防止は保証しないため、他タブを閉じる確認が必要。
- 確認中に3領域の内容が変わった場合は、復元を始めず再確認を求める。失敗時の回復も容量やブラウザ設定に依存するため、外部ファイルのバックアップを推奨する。
- FREE最大10万件の検証を自動テストした。検証を通ることと、そのブラウザのlocalStorage容量に収まることは別である。
